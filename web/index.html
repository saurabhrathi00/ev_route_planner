The drive

conditions

Leave traffic on Work it out for me and the app decides from your departure time — with a Google key it uses the delay Google measured for that hour, otherwise a rule of thumb from the clock. Override it if you know better than both.

Leave departure empty for now. Setting it matters more than it looks: the app fetches the temperature and wind for the hour you will actually be at each point, and a hot afternoon can cost several points of charge more than the same drive at dawn.

Chargers are off by default — the plan still tells you where you drop to your floor, what to charge to and where to look. Switch it on to have the app find and rank actual chargers, which adds a few seconds.

Speed comes from your driving style — gentle means both softer acceleration and a lower cruise. The router's own speed for each road still wins where it is lower, so nobody cruises at 82 km/h through a village.

Battery figures are usable capacity, not the nameplate number — a Curvv EV 55 gives about 52 kWh. Only the Curvv figure is confirmed; the rest are estimates, so correct yours if you know it.

On board

Two real trips in the same car fix the model. Trip A should climb; trip B should be flat. Driving time matters more than anything else here — the model needs the average speed each trip actually ran at, not the speed you held on the good bits.

Where data comes from

google or free

Free is the default and costs nothing: OpenStreetMap tiles, OpenRouteService or OSRM routing, Photon place search, Open Charge Map and OpenStreetMap chargers. No key, no account, no bill.

Chargers uses your Google key for charger lookups only — and only when charger search is switched on. This is the setting worth having: outside the big cities the free charger databases are often empty where Google has a dozen, with star ratings and live free-bay counts. Needs Places API (New) on the key.

Everything adds Google routing, place search and a Google map on top. Place search is noticeably better for Indian town names; routing and the map are close to the free ones, so this mainly costs more. Needs Routes API and Maps JavaScript API as well. Set a daily quota cap on each.

Reverse place-naming always uses the free service: Google's Geocoding API refuses browser requests, so it cannot be called from here at all.

Services

built in

Everything works without this. A key makes three things better: routing uses Google instead of OpenStreetMap data, place search finds Indian towns far more reliably, and the map becomes a real Google map. It also adds star ratings and live bay counts to chargers.

Your key never reaches us. It cannot.
  • There is no server. This app has no backend of any kind — nothing to send a key to, and no account behind it. Every calculation happens on this device.
  • The key is written to this device's local storage and nowhere else. Clearing the box above, or uninstalling, erases it.
  • It is attached to requests going to googleapis.com only — Google's own servers. Nothing else, ever.
  • Billing stays between you and Google. We cannot see your usage, and you can revoke the key in the Cloud console at any moment.

Do not take our word for it — the whole app is one readable file: read the source. Search it for gkey and you will find every place the key is used.

Get one at console.cloud.google.com and enable Routes API, Places API (New) and Maps JavaScript API. Google bills these to you, so set a daily quota cap on each.
